# D3 前置实验报告：关节刚度配置值的实际单位

> 实验脚本：`scripts/d3_probe_drive_units.py`
> 原始输出：`docs/D3-probe-raw-output.log`，结构化结果：`docs/drive_unit_probe.json`
> 硬件：RTX 3090 / Isaac Sim 4.5.0 / Isaac Lab v2.1.0 / Python 3.10.21
> 结论一句话：**Isaac Lab 的 `ImplicitActuatorCfg.stiffness` 单位是 N·m/rad，可以按物理直觉直接填。**

---

## 一、为什么必须先做这个实验

Isaac Lab 的 `ImplicitActuatorCfg.stiffness` 写进 PhysX 时，单位到底是 N·m/rad 还是 N·m/deg？
两者相差 **180/π = 57.296 倍**。

这个数字对 Poppy 是决定性的：它腿上主要是 Dynamixel MX-28，堵转力矩约 **2.5 N·m**。
如果配置值被当成 N·m/deg，那么写 `stiffness=8` 实际得到的是 **458 N·m/rad** —— 比真实电机强 180 倍，
仿真会在第一次迭代就爆掉，而表现看起来就像"关节乱甩 / 反关节站不稳"。

开工前手上有两条**互相矛盾**的线索：

| 线索 | 说明 |
|---|---|
| `convert_urdf.py --joint-stiffness 8.0` | 生成的 USD 里写成 **0.139626**（= 8.0/57.296）。源码注释 `# N-m/rad --> N-m/deg` 表明转换器认为 **USD 的角度驱动刚度是 N·m/deg** |
| `Articulation.write_joint_stiffness_to_sim()` | 把配置值**原样**写进 PhysX 张量接口，全仓库搜不到任何换算代码 |

光读代码无法定论 —— 所以直接测物理响应。

## 二、测量原理（外部已知力矩法）

对**基座固定**的串联链，施加在某根连杆上的力矩，会**完整地**传递给链条上所有与该力矩轴平行的关节；
与之垂直的关节几乎不承受（力矩平衡原理）。稳态时角速度为零、阻尼项不贡献力矩：

```
|tau_ext| = kp_eff × |Δθ_rad|      →      kp_eff = |tau_ext| / |Δθ_rad|   [N·m/rad]
```

于是：

- 把所有关节刚度**统一**设为 S（不需要把其余关节搞成刚性 —— 见第四节）
- 关掉重力、把骨盆固定在世界坐标系（`fix_root_link=True`）
- 在小腿上施加已知力矩，读稳态偏角
- 用 S=8 与 S=16 各测一次，看 **c = kp_eff / S**：
  - c ≈ 1.0 → 配置值就是 N·m/rad
  - c ≈ 57.296 → 配置值被当成 N·m/deg

**这个方法的价值：只看物理响应，不依赖任何"读回来的数字"。**

## 三、实验结果

### 3.1 read-back：Isaac Lab 确实原样写入

```
stiffness : [8.0, 8.0, 8.0, 8.0, 8.0, 8.0, 8.0, 8.0, 8.0, 8.0]
damping   : [0.3, 0.3, 0.3, 0.3, 0.3, 0.3, 0.3, 0.3, 0.3, 0.3]
```

PhysX 里真实生效的就是配置值本身，没有换算。但"原样写入"不等于"N·m/rad"，单位要靠下面的响应判定。

### 3.2 力矩轴扫描（关键一步）

Isaac Lab 的**外部力矩作用在刚体自身坐标系**下（不是世界系）。小腿的局部 Y 轴沿骨头方向，
绕它加力矩等于"拧大腿"—— 第一版实验就是这么翻车的。自动扫描三个体轴后：

| 施加轴 | 主要响应关节 | Δθ [rad] | kp_eff [N·m/rad] | kp_eff/S |
|---|---|---|---|---|
| 刚体 X | **r_hip_x** | +0.2498 | **8.007** | **1.001** |
| 刚体 Y | r_hip_z（只承担 43%） | −0.1077 | 18.575 | 2.322 |
| 刚体 Z | **r_hip_y** | −0.2805 | 7.131 | 0.891 |
| 刚体 Z | **r_knee_y** | −0.2474 | **8.083** | **1.010** |

⇒ **膝关节的俯仰轴是刚体 Z 轴**；刚体 X 轴与髋侧摆同轴。

### 3.3 两个刚度的绝对值测定（两个关节互相印证）

载荷：[0, 0, +2.0] N·m（绕刚体 Z 轴，方向为膝盖的**可弯方向**）

| 配置 S | r_knee_y Δθ | kp_eff | c = kp_eff/S | r_hip_y Δθ | kp_eff | c |
|---|---|---|---|---|---|---|
| 8.0 | −0.24744 rad (−14.18°) | 8.083 | **1.010** | −0.28045 rad | 7.131 | 0.891 |
| 16.0 | −0.12240 rad (−7.01°) | 16.340 | **1.021** | −0.14192 rad | 14.093 | 0.881 |

**刚度翻倍，偏角精确减半** —— 线性关系成立，说明测量的是真实的弹性刚度，没有混入摩擦或限位效应。

**平均换算系数 c = 0.951 ≈ 1.0。**

### 3.4 结论

> **`stiffness` 的单位就是 N·m/rad。想要 8 N·m/rad 就写 `stiffness=8.0`，不需要任何换算。**

四个独立测量值（两个关节 × 两个刚度）落在 0.88–1.02 之间，其中髋侧摆那次（1.001）和膝盖那次（1.010）误差在 1% 以内。
一个关节处在链条根部、轴与力矩完全对齐，理论上不应有分配误差 —— 它给出 1.001，这正是方法的自校验。

### 3.5 附带的第二项结论：反关节在物理上被堵死

把膝盖目标设到限位之外，看仿真是否真的拦住：

```
目标 r_knee_y = +0.500 rad (+28.6°)  →  实际 +0.0611 rad (+3.50°)   ← 被卡住
目标 r_knee_y = -0.500 rad (-28.6°)  →  实际 -0.5000 rad (-28.65°)  ← 正常到达
```

膝盖限位是 `[-2.339, +0.061]` rad（总行程 134°，反向余量只有 3.5°）。
**仿真里"反着弯膝盖"这条作弊解被封死了** —— 这是 D2 结论的物理实证，
也意味着 D3 训练如果再出现反关节，原因只可能是 PD 增益量级错误，不会是限位问题。

## 四、两个被实验否定的方法学假设（值得记住）

**① 不需要把其余关节设成刚性。**

第一版为了把载荷"隔离"到单个关节，把其余 9 个关节刚度设成 `1e5`。结果求解器被这种极端刚度拖死：
**225 ms/步**，跑 27 分钟还没结束。改成"统一刚度"后是 **4–7 ms/步**，快了 30–50 倍。

理论依据：串联链上与该力矩轴平行的关节**会各自承担全部力矩**，所以不需要隔离 —— 反而多了一路交叉验证
（膝盖和髋给出两个独立估计）。**用物理性质换掉数值技巧，是这类实验的正确姿势。**

**② 外部力矩在刚体坐标系，不在世界坐标系。**

第一版按"世界 Y 轴"施加，结果力矩全被 `r_hip_z`（髋偏航）吃掉，膝盖纹丝不动。
根因是小腿的局部 Y 轴沿骨头方向。教训：**涉及坐标系的问题不要靠推理，用扫描把它测出来** ——
三轴各跑一次只要十几秒，比读文档快得多。

（顺带解释了那个 2.322 的"异常值"：它不代表单位问题，而是该轴与关节轴只对齐了约 43%，
关节只承担 43% 的力矩，用总力矩去除自然偏大 2.3 倍。轴对齐好的两次立刻回到 1.0。）

## 五、对 D3 训练配置的直接影响

1. **PD 增益可以按物理直觉直接填**：D2 审计里按重力力矩估的起始值（`hip_y` kp≈20，其余 kp≈8，单位 N·m/rad）
   现在可以直接用，不需要除以 57.296。仍然建议 ±50% 扫一轮验证。

2. **力矩上限要在配置里收紧，不要改 USD。** URDF 写的是 `effort 3.1 N·m`（髋部 7.3），
   而 MX-28 实际堵转约 2.5 N·m、MX-64 约 6 N·m。用 Isaac Lab 的 `effort_limit` 参数覆盖即可：
   比手工改 USD 更清晰，也更容易做域随机化（训练时随机 0.8–1.2 倍电机强度）。

3. **kp=8 N·m/rad 对 MX-28 已经是"偏硬"的档位**：0.3 rad（17°）的位置误差就会要求 2.4 N·m，
   接近堵转。这从另一个角度解释了为什么照抄大机器人的 kp（几十上百）必然爆掉。

4. **关节限位表已逐项记录**（见 `docs/drive_unit_probe.json`），训练时可直接用于软限位与终止条件。

## 六、一个需要写进文档的"层间单位陷阱"

三层对同一个物理量的单位约定并不一致：

| 层 | 单位 | 证据 |
|---|---|---|
| URDF / Isaac Lab 配置 | **N·m/rad** | 本实验实测，c ≈ 1.0 |
| `convert_urdf.py` 的输入 | **N·m/rad** | 文档与默认值 |
| USD 里的 `drive:angular:physics:stiffness` | **N·m/deg** | 转换器写入 0.139626 = 8/57.296，源码注释 `# N-m/rad --> N-m/deg` |
| PhysX 张量接口 / Isaac Lab 写回 | **N·m/rad** | 本实验实测 |

这套约定本身是自洽的（转换器在边界上做对了换算），但**陷阱在于**：
直接打开 USD 看到 `stiffness = 0.139626`，把它抄进 Isaac Lab 配置，就会得到**软 57 倍**的关节 ——
而且是"看起来能跑、只是站不住"这种最难查的故障模式。
只要记住"**配置层永远是 N·m/rad，USD 里的数不是给人抄的**"就不会踩。
