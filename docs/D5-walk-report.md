## 0. 一句话结论

行走任务一共迭代了 9 个版本（v1–v9），前六个版本策略分别学会了**滑行、单腿跛行、小碎步、动作符号作弊、右倾踩空、可定价的扫地式跛行**；
v7 把「双脚承重对称」从**奖励惩罚**升级为**终止条件**（奖励可以被策略"定价"忍受，终止不能），收敛出双足交替承重——
但随后发现 v7 的"行走"是**横向移动**：基座坐标系与解剖学朝向差 90°，v1–v7 的"前进"指令全发在了身体侧向（§8.1）。
v8 按相机标定"前方=+y"把指令换到 y 通道——但**标定是肉眼判的，判反了**：v8 学的是**倒走**（§9.1）。
v9 用 URDF 正运动学终裁（默认站姿下膝盖朝基座 **−y** 凸出 = 解剖学前方，与仿真基座高度交叉自洽），
指令翻号微调后得到**真·前进行走**：0.296 m/s（指令 0.25）、双脚交替占空比 44%/43%、抗扰 100% 存活。
此外还揪出判卷工具自身的两处缺陷：接触力索引 bug（§4）与指令通道写死 bug（§8.3）——
**测量工具也要被审计**，是本冲刺贯穿始终的教训。

## 1. 任务设定（与站立任务的关系）

站立 = 速度指令恒为 0 的跟踪任务；行走 = 同一个 MDP 把速度指令换成非零。
共用资产（10 DOF 锁腿版）、PD 增益、终止条件（摔倒 / 朝向 / 过低），差异集中在：

- **速度指令** `lin_vel_x ∈ [0.2, 0.2]`（训练初期固定，便于读 reward 收敛曲线）
- **步态奖励**（v1–v7 迭代的主体，见 §2）
- **v7 终止项** `single_leg_lean`（§2.4）

训练规模：2048 并行环境 × 2500 迭代，RSL-RL PPO。
宿主机故障期间（PCIe 16x→8x）迭代时间 1.5~5 s/轮波动，全程 ~2 h。

## 2. v1–v7 失效模式史（本报告最有价值的部分）

RL 调试的核心教训：**每次你以为奖励设计已经堵死了作弊路径，策略会找出一条你没想过的新路径**。
每个版本按「现象 → 排查 → 真凶 → 修法」记录。

### v1：滑行（skating）

- **现象**：机器人双脚贴着地面向前蹭，速度奖励满，物理上是"冰上滑行"不是走。
- **真凶**：速度奖励只奖励 `v_x`，没有任何项要求脚离地。
- **修法**：加 `feet_air_time_landing`（只在**落地瞬间**给悬空时间奖励，避免在空中持续给分诱发踢踏舞）。

### v2：单腿跛行（hopping on one leg）

- **现象**：右脚跳、左脚拖行。速度达标，但左右严重不对称。
- **真凶**：air-time 奖励对左右脚求和，单腿跳是合法的局部最优。
- **修法**：发现 `clamp(min=0)` 把负梯度截断了（脚迟迟不落地时奖励恒定，策略不知道要落地）→ 改 `clamp(max=...)` 只截上限。

### v3：小碎步（tip-toe shuffling）

- **现象**：双脚都着地了，但步幅极小、原地高频踏步，几乎不前进。
- **真凶**：air-time 上限（0.5 s）给得太大，策略靠"快踩快抬"白嫖落地奖励，不靠前进。
- **修法**：收紧 air-time 上限 + 加重速度跟踪项相对权重。

### v4：奖励符号错误（自己埋的 bug）

- **现象**：v3 的修法让情况更糟——策略倒退着走。
- **真凶**：hover 惩罚改成"返回正 excess 配负权重"时，负×负=正，**惩罚项实际在奖励悬空**。
- **修法**：修正符号，并立规：奖励项改动必须配一份"该项的解析梯度方向"推导，防止此类 bug。

### v5：右倾踩空（lean-and-hover）

- **现象（当时基于错误测量得出的诊断）**：左脚"全程 0N、悬空 7mm"，右脚单腿支撑。
- **排查**：零动作探针（`probe_zero.py`）证明资产左右对称（脚高差 0.13mm），排除资产问题；
  发现训练时随机推力会造成"假擦地"，重置接触传感器的 air_time 计时器，使悬空惩罚失明。
- **修法**：v6 改测**受力对称性**而不是悬空时间（见下）。
- **事后更正（2026-09-20，修正判卷脚本后回测 v5 checkpoint）**：
  "左脚 0N"实为误测右小腿（§4 索引 bug）。v5 的真实步态是**双脚交替但承重严重不均**：
  左脚平均 7.6 N（承重占空比 30%）vs 右脚 18.6 N（73%），z 相关 −0.51 反相交替，12 s 全存活，0.258 m/s。
  即 v5 的问题从来不是"左脚踩空"，而是**右倾偏载**——v6/v7 的对称性约束方向依然正确，
  只是把左脚承重占比从 29% 一路修到 42%（v7），离完美对称尚有差距。

### v6：可定价的惩罚（priced penalty）

- **改动**：`feet_loading_symmetry`（左右脚竖直接触力的 2 s EMA 差 / 体重，超 0.25 阈值惩罚，权重 −2.0）
  + `base_roll_penalty`（基座横滚角惩罚，权重 −1.0）。
- **现象**：判卷仍不通过（旧尺子的口径），但奖励日志揭示了更深的问题：
  **惩罚是"可定价"的**——策略宁可每步交 0.01 的不对称罚金，也要换 1.46/步的速度奖励，
  左脚贴着地"扫"（有接触但不承重），罚金极小、速度照赚。
- **真凶**：奖励语言里任何有限的惩罚都能被更大的奖励对冲掉。要禁掉一种行为，要么惩罚足够大（但会破坏奖励景观的可学习性），要么……
- **修法**：v7 把该行为直接定义为**回合终止**——终止不可被定价。

### v7：终止条件封杀（termination is not priceable）✅

- **改动**：新增终止项 `single_leg_lean`——任一脚的承重 EMA（α=0.99，时间常数 ~2 s）在 2.5 s 热身后低于 18% 体重，立即终止回合。
  数值核算：正常交替步态每脚 EMA ≈ 0.5 体重，安全余量 2.8×；随机推力造成 <2 s 的短暂卸载不会误杀。
- **结果**：训练曲线回合长度持续上升至接近满回合（policy 学会了始终让双脚承重 EMA 高于阈值），判卷通过（§3）。
- **教训**：**奖励是定价语言，终止是法律语言**。想让策略彻底放弃一种作弊模式，把它从"罚款"升级为"死刑"。

## 3. v7 判卷结果（修正后的尺子）

评估：`scripts/d5_eval.py --headless --checkpoint model_2400.pt --vx 0.2 --duration 12`，
Play 环境（确定性策略，无推力），8 并行环境。

| 指标 | 结果 | 判据 | 结论 |
|---|---|---|---|
| 存活率 | 8/8 撑满 12 s（100%） | 不倒 | ✅ |
| 左脚平均接触力 | 10.6 N | > 0 | ✅ |
| 右脚平均接触力 | 14.5 N | > 0 | ✅ |
| 左右脚 z 相关系数 | −0.49 | 反相交替 | ✅ |
| 净前进速度 | 0.289 m/s（12 s 走 3.47 m，8 环境极差 < 0.006） | ~指令 0.2 | ✅（略超指令 45%） |
| 基座高度 | 0.421 ± 0.0015 m | ≈ 标定 0.4192 | ✅ |

**步态定性**（以 `traces.png` 逐帧曲线为准）：~3 Hz 快步频交替步态——
完整左右步周期约 0.33 s，双脚 z 高度反相振荡（抬脚 6~10 mm），基座速度围绕均值 ±0.05 m/s 规律波动，
基座高度 0.420~0.4245 m 节律起伏。步长约 0.29 m/s × 0.33 s ≈ 9.6 cm，属小步快走式动态步态，
右脚承重占比偏高（mean 14.5 N vs 左脚 10.6 N），左右尚不完全对称。

> ⚠️ 更正记录（2026-09-20）：早先基于 `probe_term.py`（每 25 步 / 0.5 s 采一次）得出的
> "一步 2~2.5 s 准静态慢走"结论系**采样混叠**（aliasing）——0.5 s 采样间隔对 0.33 s 周期信号
> 产生虚假慢波，还一度造成"EMA 对零输入反而上升"的假象。教训：探针采样率必须高于被测信号
> 最高频率的 2 倍（奈奎斯特），步态类信号直接看逐帧曲线，不要用稀疏采样点推断相位。
**诚实标注**：此判定基于确定性策略、无外力扰动的 12 s 窗口；带噪 / 抗扰表现见 §5。

## 4. 判卷工具索引 bug（方法论教训，本次最大收获）

### 现象
v7 判卷显示"左脚 0N、悬空 100%"，但 12 s 全存活——与 `single_leg_lean` 终止项矛盾
（左脚真 0N 应该在 2.5 s 被判死）。矛盾点就是线索。

### 排查（脚本：`scripts/probe_term.py`）
写一个活体探针，逐帧打印终止项的**全部中间量**（两脚受力、EMA、体重、比值、warmup 标志、返回值），
并审计三套刚体 ID 的口径：

```
robot.find_bodies(".*foot")        → ids [9, 10]  （机器人本体顺序：l_foot=9, r_foot=10）
sensor.find_bodies([l_foot,r_foot]) → ids [5, 10]  （传感器顺序：跟踪全部 11 刚体，l_foot=5）
```

`d5_eval.py` 用 **robot 的 ID [9,10] 去索引传感器的 `net_forces_w`**——
传感器数组里 9 号是 **r_shin**（右小腿，永远不受力），10 号恰好是 r_foot。
于是"左脚受力"其实一直在测右小腿，"右脚"反而是对的。

### 影响面
**v5–v7 三轮判卷的"左脚全程 0N"结论全部无效**；z 高度数据（robot ID 索引 `body_pos_w`，口径正确）不受影响。
终止项本身工作完全正常（探针实测双脚承重比 0.20~0.45，均在 0.18 阈值之上）。

### 修法
取接触力必须用 `sensor.find_bodies`（传感器自己的 body 顺序），取位置仍用 `robot.find_bodies`，两者分开。
已提交（commit `d30f3e8`）。

### 可复用的规律（方法论铁律第四案）
1. **测量工具也是程序，也会写错**——争议出现时，测量工具本身列入嫌疑清单，与策略、资产平级。
2. **量纲/索引口径审计**：跨对象（robot vs sensor）的索引，必须显式验证顺序映射，不能假设一致。
3. **矛盾即线索**：两个独立测量（终止项 vs 判卷脚本）给出矛盾结论时，不要急着选边，写探针把两边中间量都打出来对质。

## 8. v8：坐标系更正（后被 §9 推翻——本节"前方=+y"结论系肉眼误判）

> 本节是 D5 里程碑的**修正与重写**：v7 的"通过"结论在本节被推翻并重立。
> 保留 v1–v7 全文作为失效模式史。**注意：本节给出的"解剖学正前方 = 基座 +y"结论，
> 一天后被证明是错的（§9.1），v8 实为倒走。保留本节原样作为教训链的一环，最终以 §9 为准。**

### 8.1 发现：肉眼看视频一帧抓到判卷盲区

2026-09-20 晚录出 v7 行走视频后，培鑫看完提出两个质疑：
**"左脚还是悬空" 和 "它怎么是横着走路的"。**

用 `scripts/probe_yaw.py` 实测：蟹行角（基座 yaw − 运动方向）**mean −0.6°、p90 5.1°**——
身体 x 轴与运动方向完全对齐；左脚 12 秒落地 52 次（截图帧恰好在摆动相）。
当时的初步结论："不是横着走，是相机摆错了方向"。

但重录侧面视频后仍然是背面视角，数学与画面矛盾。
**把争议前提单独变成可测量量**（方法论铁律）：
写了相机标定实验 `scripts/cam_calib.py`——机器人保持同一姿态，从体坐标
前后左右四个方位各渲染一帧：

| 相机位置（体坐标） | 画面 | 结论 |
|---|---|---|
| +y | **当时判为"正面照"**（白色机器人正/背面特征弱，肉眼难辨） | ~~解剖学正前方 = **+y**~~ **（错误，§9 终裁为 −y）** |
| −x | 标准侧面轮廓 | x 轴 = 身体侧向 |

**实锤（一半对一半错）：基座坐标系比解剖学朝向歪了 90°（前方在 ±y 轴上，不是 +x）——
90° 的定性是对的，但符号判反了：真正的前方是 −y（§9.1）。**
而 v1–v7 的"前进"指令 `lin_vel_x=0.2` 发在基座 x 通道上，
等于命令机器人"向自己的侧向横移"——策略**精确执行了这条歪指令**，
学出一套 ~3 Hz 横向交叉步。所有判卷指标（速度大小、双脚交替、存活、承重对称）
都对朝向盲，所以一路绿灯；肉眼看视频一帧就抓出来了。
**培鑫的质疑是对的——v7 真的是在横着走。**

方法论第五案：**判卷没测的量，肉眼一帧就抓出来了。**

### 8.2 修复：指令换通道（奖励零改动）

`track_lin_vel_xy_exp` 用的是 xy 平面速度范数，指令换通道后奖励**一行都不用改**。
原设计"锁死横向指令防侧移"的意图本身正确，只是当年贴错了轴：

```python
# walking_env_cfg.py  v7 → v8
lin_vel_x=(0.0, 0.35),  →  lin_vel_x=(0.0, 0.0),   # 解剖学横向，锁死防横漂
lin_vel_y=(0.0, 0.0),   →  lin_vel_y=(0.0, 0.35),  # 解剖学前向 = 基座 +y
```

### 8.3 判卷工具第二个 bug：指令钉死通道的过时假设

v8 训完第一次判卷显示"慢速蹭步 0.054 m/s"。排查发现
`d5_eval.py` 与 `record_walk.py` 的 `pin_command()` **把指令写死钉在 x 通道**
（旧的"前进=x"假设），覆盖了环境配置——策略收到训练时从未见过的指令
（训练时 x 恒为 0），给出分布外的保守行为，被误判为"没学好"。
修正 pin_command 后重测，真实水平显现（§8.4）。

这是"测量工具也要被审计"的第六案：**判卷工具自身携带过时的坐标系假设，
工具不跟着改，环境改对了也没用。**

## 9. v9：肉眼复核再立新功——"倒走"发现与运动学终裁（2026-09-21 晚，最终版）

> §8 交付当晚，培鑫看 v8 视频提出第三个质疑：**"它好像是倒着走的。"**
> 他再一次对了。本节是 D5 的第二次重写，也是最终版。

### 9.1 发现：脚尖朝一边，人走另一边

逐帧放大 v8 视频：脚掌（脚尖）清晰指向屏幕一侧，而机器人位移朝另一侧——
朝一个方向、走另一个方向，即**太空步式倒走**。
§8 的相机标定把白色机器人的背面误判成了正面（正/背面渲染特征太弱），
"前方 = +y"整个是反的；v8 指令 vy=+0.25 实为命令机器人**朝自己的背后走**，
策略又一次精确执行了歪指令。

### 9.2 终裁：不用眼睛，用运动学

朝向问题两次栽在"看渲染图"上，这次换成纯几何——URDF 正运动学：
默认站姿（hip_y=+0.10、knee=−0.20、ankle_y=+0.10，骨盆高度取标定值）下逐关节算变换：

- 髋 pitch 轴、膝轴、踝轴在骨盆系下全部平行（结构自洽）；
- **膝盖关节点朝基座 −y 方向凸出 ~1.8 cm，小腿朝 +y 后摆**——
  屈膝时膝盖凸出的方向就是解剖学前方（膝盖朝前、脚跟朝屁股），
  故 **解剖学正前方 = 基座 −y**；
- 交叉验证：算出的踝关节高度 −0.383 m + 脚掌厚度 ≈ 仿真实测骨盆高 0.419 m ✓；
  右腿位于 −x 侧（前方 −y × 上 +z → 右侧 = −x）✓，全套右手系自洽。

**方法论第七案：朝向判定不许用眼睛看渲染图（白色机器人正背面会判反），
必须用运动学几何（膝盖凸出方向）裁决。**

### 9.3 零成本测试：符号无泛化，必须重训

先给 v8 冻结策略直接发 vy=−0.25（真正的前方）：100% 存活但 mean_vy = **+0.045 m/s**——
原地踏步、拒绝执行（符号对策略是分布外输入）。白嫖失败，需要微调。

### 9.4 修复与微调（用户拍板：从 v8 微调而非从头重训）

指令翻号（commit `860685c`）：`lin_vel_y (0,0.35) → (−0.35,0)`，Play 固定指令 vy=−0.25，
判卷/录视频默认值同步翻号。从 model_7498 resume 微调 **+2500 轮**（共 ~10000 轮，34 min @ 0.82 s/轮）。
训中跟踪奖励 1.43/1.5、error_vel_xy 0.139——微调很快咬住了新方向。

### 9.6 朝向问题三次迭代总账（本项目最贵的一课）

| 版本 | 指令 | 实际行为 | 怎么发现的 |
|---|---|---|---|
